01背景与目标

百业战是 30 人规模的团队玩法，胜负依赖赛前分工与临场调度。没有统一战术图时，信息会散落在截图、语音和聊天记录里，难以复用，也难以向新队员解释。

1.1 观察到的现状

  • 信息分散：路线、集合点、偷塔人选、首领争夺时间常以“截图 + 手画 + 口头描述”传播，队员看到的版本不一致。
  • 复用困难：上一场的战术图无法按分类归档，也无法快速复制成“下一场只改两个人”的新方案。
  • 表达不精确：“上路靠前一点”“中路集合”缺少统一点位，队员对同一描述的理解可能不同。
  • 流派与人员脱节：名单在群公告里，站位在图上，二者对不上；临时换人时无法快速找到对应标记。

1.2 产品决策

做什么

做一个无需登录、打开即用的网页战术沙盘：模板库分类管理；一张百业战示意地图；可放置地图标点与流派人物；可画路线、写文字；自动保存到浏览器；用 JSON 文件导入导出。

为什么这样做

战队传播战术图最可靠的方式仍是“发文件”。纯前端 + 本地存储可以避免账号、服务器与隐私成本；JSON 文件便于在群聊中转发，也为后续分享链接与云端协作留出升级空间。

1.3 目标（可观察）

  • 指挥不依赖外部绘图软件，就能完成一张包含路线、资源点、流派人物与备注的战术图。
  • 队员导入同一个模板文件后，看到与指挥端一致的对象位置、名称与图层状态。
  • 上一场的模板可以被复制、改人名、改路线后再次使用，不需要从空白开始。
  • 刷新页面或重新打开浏览器后，最近一次成功保存的模板仍然存在。

1.4 不做什么（P0 边界）

  • 不接入游戏账号、对局数据或录像，不做自动复盘、胜率预测或自动指挥。
  • 不做实时多人协同、云端同步、公会/战队账号体系。
  • 不使用官方地图原画、Logo 或角色立绘；地图为自制结构示意。
  • 不做移动端完整编辑；P0 以桌面浏览器为主。
  • 不提供“官方认证战术”或强度结论；流派预设只是快捷标签。

02玩法与流派研究

这一节不是游戏百科，而是把公开机制翻译成产品约束：地图要表达什么、标点要覆盖哪些对象、人物名单要支持怎样的规模、模板分类应如何组织。

2.1 百业战机制摘要

机制公开资料摘要对产品的设计含义
30v30 团队竞技 双方各 30 人，以百业为单位参战；历史公告称百业人数上限曾扩至 80 人，赛前需要从名单中挑选出场人员。[1][3] 人物标记至少支持 30 人以上；需要花名册、分组、筛选与批量添加，避免逐个创建。
三路与人墙 攻略提到可“偷其余两路塔”，官方更新提到“上下两路”新增据点，说明战场存在上、中、下三路结构；每方三座人墙。[1][2][4] 地图必须表达三路、每方三座人墙；标点支持“人墙”类型与“完好/受损/已摧毁”状态，便于做阶段方案。
胜负条件 击杀敌方大鹅后，将敌方发财树搬回并穿过己方大门即获胜；时间结束则比较双方人墙、大鹅血量，或发财树更接近哪方复活点。[1][2] 需要“大鹅”“发财树”“大门/复活点”标点，以及“搬运路线”这类专用路线；模板分类中应有“终局搬树”。
人墙机制 摧毁任意一座人墙即可对敌方大鹅造成伤害；摧毁三座后大鹅被大幅削弱。官方更新提到人墙会按附近敌我人数叠加减伤，击破后对大鹅有更强削弱。[1][4] 人墙标点需要状态与备注；“先破一路还是三路全破”应能在同一张图上用路线和文字表达。
中立资源 张豹、朱邪骨勒提供大量逗币；朱邪骨勒额外提供团队增伤，常被视为翻盘资源；刷新位置不固定，官方更新调整为原刷新时间前后 1 分钟随机。[1][4] 需要中立首领标点，并允许标注“张豹/朱邪骨勒”“争夺/已击杀”“预计刷新”等备注；野区位置用区域而非固定点表达。
玄元教据点 上、下路据点，开局 3 分钟后刷新；占领后可选择在据点复活；占领后 1 分钟内不可变更归属。[4] 需要“据点”标点与“中立/我方/敌方”状态；可作为复活点与转线节点。
中场演出 官方称“中场演出”，攻略常称“中场表演”；由社主指定人选参与，胜负可直接影响敌方人墙或大鹅血量。[1][4] 需要“中场演出”事件标点，并能在人物花名册中标记“中场人选”。
指挥与逗币 击杀玩家、野怪、首领获得逗币；仅指挥可消耗，施放全队增益、搬树加速、打鹅增伤、快速复活、攻防指令等；官方提到指挥技能“无视拦截”和“快速操作”模式。[1][4] 人物定位中需要“指挥”；标点中可加入“指挥技能”说明点；备注用于记录技能时机与目标。
阶段节奏 攻略通常把对局分为前期（打塔、打野、存逗币、偷塔）、中期（破至少一座人墙、中场演出、争夺张豹）、后期（破余塔、争夺朱邪骨勒、杀鹅搬树）。[1][2] P0 用模板分类 + 备注表达阶段；P1 增加“前期/中期/后期”方案页或图层，避免一张图过载。

2.3 对设计的直接影响

地图要像“结构图”

三路、三座人墙、双方基地、野区首领、上下路据点、中场事件必须一眼可辨。底图不能只是一张风景图。

人物要能“成组”

30 人规模下，逐个加人不可接受；需要按流派批量添加、自动编号、分组筛选与花名册定位。

表达要覆盖“阶段”

前期偷塔、中期首领、后期搬树是不同任务；P0 用分类和备注承载，P1 用阶段图层拆开。

03用户与核心场景

产品的核心不是“画图”，而是让指挥把脑中的分工变成一张队员能照着执行的图。因此所有角色都围绕同一份模板文件协作，只是动作不同。

3.1 用户角色

角色目标关键动作典型时刻
社长 / 指挥赛前把 30 人分工讲清楚，临场能快速调整新建/复制模板；分配路线与人；标注资源点与集合点；导出后发群；赛后改图复盘比赛前 1 天、开赛前 30 分钟、局间休息
战队队员快速看懂“我去哪、什么时候去、和谁一起”导入模板；查看地图与花名册；按路线执行；把自己的名字/流派核对一遍赛前查看、比赛中查看
战术整理者把有效打法沉淀成可复用资料按分类归档；复制旧模板改版本；补充备注；整理“开局/偷塔/搬树”系列赛后复盘、赛季准备
新队员理解百业战的基本点位与流派分工打开只读模板；逐层查看标点与人物；对照图例学习入队培训
权限说明：P0 是单用户本地工具，不做账号与角色权限。所谓“队员”是通过收到 JSON 文件并在自己的浏览器导入来查看；文件本身即分享边界。P2 若做云端协作，再引入“只读链接/编辑权限”。

3.2 核心场景

场景 A · 赛前分工

指挥从“开局布防”分类复制上一场的模板，改名为“对 XX 社 · 三路开局”。把 30 人按流派批量加进花名册，拖到上/中/下路；用箭头画出偷塔路线，用“据点”标出玄元教刷新位置；导出 JSON 发群。

场景 B · 局间调整

第一局发现上路被针对。指挥复制当前模板，把“翊1号”和“双剑1号”换到中路，新增“集合”标点，备注“张豹刷新前 30 秒集合”，导出第二版。

场景 C · 赛后复盘

战术整理者打开“终局搬树”模板，用“大鹅/发财树/路线”复盘最后一波：标出失败点、敌方拦截点，另存为“复盘 · 搬树被拦”，归入“赛后复盘”。

3.3 核心任务流程

进入模板库→ 选择分类 / 搜索→ 新建或复制模板→ 在地图上放标点 / 人物 / 路线→ 自动保存→ 导出 JSON→ 队员导入查看

完成条件：队员导入后，地图对象的位置、名称、颜色、图层显隐与指挥端一致；刷新页面后，本机模板仍在。

3.4 关键设计取舍

取舍选择理由与代价
本地优先 vs 云端P0 浏览器本地存储 + JSON 文件零登录、零服务器、隐私简单；代价是换设备/清缓存会丢数据，需要显式提醒导出备份。
示意地图 vs 精确复刻P0 自制三路结构示意底图避免版权风险，先保证“能讲清战术”；代价是与游戏内地图不完全一致，精确底图列为 P2/待确认。
固定画布 vs 无限画布固定比例战术板，坐标归一化不同屏幕导入后位置一致；代价是不能画地图外的内容，符合“一张地图一个模板”的定位。
流派硬限制 vs 可编辑标签预设 + 自定义，可改简称与颜色游戏版本会新增/调整流派；硬编码会很快过时，可编辑标签更耐用。
单图 vs 多阶段P0 一张图；P1 阶段图层P0 先用分类和备注表达前/中/后期，避免第一版就做复杂的多页状态；P1 再拆阶段。

06UI 设计

视觉方向是“墨线沙盘”：像铺在桌上的宣纸地图，用墨线、朱砂与青绿区分敌我，而不是复刻游戏内 HUD。所有线框只用于评审布局与交互，不代表最终视觉稿。

6.1 设计原则

地图优先

编辑器中央画布应占据最大面积；左右面板可折叠但不能挤压地图到不可用。用户打开页面第一眼应看到战场，而不是表单。

一屏完成

放点、改属性、看花名册都在同一屏完成；不因“编辑人物”跳到新页面。弹窗只用于新建、导入、导出等一次性动作。

状态可见

选中、拖拽、保存中、已保存、导入失败、存储失败都要有明确反馈；不能让用户猜“刚才那下有没有生效”。

不依赖颜色

敌我、流派、对象类型同时用图标形状、文字标签与颜色表达；色弱用户也能区分。删除模板/分类必须二次确认。

6.2 色彩系统

主色取自宣纸、墨、朱砂与青绿；朱砂只用于“敌方/进攻/危险”等高注意力信息，避免整页发红。

FR-02 模板的新建、改名、复制与删除 P0

目的：用最低成本完成“从空白开始”和“在旧图上改一版”两件事，避免每场从零画。

新建

  • 点击“新建战术”打开弹窗：模板名（必填，1–40 字）、分类（必填，默认当前分类或“未分类”）、地图（P0 只有“百业战 · 三路示意”）、描述（可选，0–200 字）、标签（可选，最多 5 个，每个 1–10 字）。
  • 创建后生成空白模板并进入编辑器；地图底图锁定，其他图层为空。编辑器显示一次轻量引导：“先放一个集合点，或从右上角添加人物”。
  • 名称为空、仅空格或超长时阻止创建；分类无效时回退到“未分类”。

改名

  • 编辑器顶部模板名可直接点击进入编辑；Enter 或失焦保存，Esc 取消。
  • 名称去除首尾空格；为空时恢复原名并提示；1–40 字。

复制

  • 卡片“复制”或编辑器“另存副本”：深拷贝模板元数据、所有对象、人物、路线、文字与图层显隐；为所有对象生成新 ID。
  • 副本命名：原名为“名称”，副本为“名称 副本”；已存在同名副本时追加序号“副本 2”“副本 3”。
  • 副本分类与原模板一致，创建/更新时间为当前时间；复制完成后留在模板库并提示，不自动打开。

删除

  • 卡片“删除”打开确认弹窗，显示模板名、人物数、标点数，并说明“删除后无法恢复，建议先导出备份”。
  • P0 删除为永久删除；确认后返回模板库并提示。后续版本再评估“最近删除/回收站”。

状态与异常

  • 模板名允许重复；列表依靠分类、更新时间与缩略图区分，不强制改名。
  • 创建/复制时若本地存储写入失败：保留内存中的草稿，提示“尚未保存”，并提供导出；不得显示为已保存。

  • 默认命名规则为“{简称}{序号}号”；同流派已有翊1号时，新增从翊2号开始续号。
  • 用户手动改过名称后，该人物不再参与自动续号；批量添加仍按当前最大序号续号。
  • 允许同名，但同一阵营出现同名时，属性面板显示非阻塞提示“同名人物”，不阻止保存。
  • 批量添加超过上限（单模板 60 人）时，只添加到上限并提示“已达人物上限”。

  • 右侧面板默认显示花名册；顶部显示“我方 N / 敌方 M / 中立 K”，并提供搜索与“队伍/阵营”筛选。
  • 每行显示：流派色点与简称、名称、队伍/阵营标签、显隐眼睛、定位。点击行选中并居中地图；再次点击不取消。
  • 眼睛图标控制该人物在地图上的显隐；隐藏不影响导出？影响：显隐状态随模板保存并导出，接收方看到相同状态。
  • 从花名册选中一个被隐藏的人物时，自动打开“人物”图层并显示该人物，同时 Toast“已显示该人物”。
  • 删除人物：无二次确认，删除后可撤销；花名册与地图同时移除。

地图标记规则

  • 圆形标记直径默认 30px；外圈 2px 表示阵营；内部为 1–2 字简称；下方名字标签带浅色底衬。
  • 拖拽移动；多个人物落在同一点时允许重叠，选中的始终在最上；从花名册定位可精确选中。
  • 修改流派时：若用户未手动改过简称/颜色，则同步更新简称与颜色；若已改过，只更新流派字段，不覆盖用户选择。
  • 修改阵营时：外圈颜色立即更新；填充色不变，除非用户选择“跟随阵营”。

异常与边界

  • 花名册为空：显示“还没有人物，按流派批量添加”；地图不显示空状态遮挡。
  • 自定义流派简称为空：阻止添加并提示；简称超过 2 字时截断为 2 字并提示。
  • 删除流派预设（自定义流派管理属于后续版本）不影响已有人物；已有人物保留名称与简称，流派字段标记为“自定义”。

FR-06 路线与文字 P0

目的：标点回答“在哪”，路线回答“怎么走”，文字回答“为什么”。三者组合才能让队员看懂一次进攻或一次搬树。

路线类型

类型默认样式用途
进攻路线朱砂实线 + 箭头偷塔、压上、集火方向
防守路线青色虚线 + 箭头回防、护塔、护树
撤退路线灰色虚线 + 箭头危险区撤离、让路
自定义用户选择颜色/线型/宽度搬树、转线、绕后等

创建与编辑

  • 选择“路线”工具 → 在地图上依次点击折点；双击最后一个点或按 Enter 完成；至少 2 个点，少于 2 个点时按 Esc 取消且不生成对象。
  • 完成后自动选中路线，右侧属性可改：名称（0–20 字）、颜色、线型（实线/虚线）、宽度（2/4/6）、是否显示箭头。
  • 拖拽折点调整路径；双击折点删除该点（至少保留 2 个点）；P0 不支持在已有线段中插入新点。
  • 删除键删除整条路线；Ctrl+D 复制；均可撤销。

文字标签

  • 选择“文字”工具 → 点击地图 → 原地输入；Enter 保存，Esc 取消；空内容不生成对象。
  • 文字 1–30 字，单行；字号 12/16/20；颜色可选；不支持富文本与换行。
  • 文字默认位于最上层，避免被路线或人物遮挡；可拖拽移动。

层级与显示

  • 渲染顺序：底图 → 区域（P1）→ 路线 → 标点 → 人物 → 文字。路线不遮挡人物与标点。
  • 路线名称显示在路径中点附近，带浅色底衬；缩放小于 70% 时可隐藏名称，仅保留线型。
  • 路线/文字随“路线与文字”图层一起显隐；显隐状态随模板保存并导出。

异常与边界

  • 路线折点拖到地图外：坐标钳制在地图内。
  • 路线名称允许重复；多条路线重叠时按创建顺序绘制，选中的路线临时置顶。
  • 文字内容只按纯文本渲染；导入文件中的 HTML/脚本字符必须转义，不能执行。

FR-07 属性面板与图层 P0

面板结构

  • 右侧面板三个页签：花名册、属性、图例。默认花名册；选中对象后自动切到属性。
  • 属性页在未选中对象时显示“未选中对象”和当前模板摘要（模板名、分类、对象数、地图版本）。
  • 选中标点/人物/路线/文字时，显示对应字段；字段分组为“基本信息 / 显示 / 备注”。

字段与联动

对象属性页字段
标点类型（只读）、名称、颜色、大小、状态、备注；位置以坐标只读显示
人物名称、流派、简称、阵营、队伍、定位、颜色、备注；显隐开关
路线名称、颜色、线型、宽度、箭头开关、备注
文字内容、字号、颜色

  • 名称/备注类字段在输入过程中允许临时为空，但失焦时若必填为空则恢复上一个有效值并提示。

  • 选中的对象被删除：属性页回到“未选中对象”，花名册计数更新。
  • 隐藏当前对象所在图层：取消选中并提示“已隐藏该图层”；对象数据不删除。
  • 撤销/重做后，属性面板同步刷新为当前对象状态；若对象已被撤销掉，则回到未选中状态。

FR-08 本地保存与恢复 P0

目的：让用户敢关页面、敢刷新；在不引入账号与服务端的前提下，把“丢了重画”的风险降到最低。

保存规则

  • 模板内容变化后自动保存到浏览器本地存储；顶部状态依次显示“保存中…”“已保存 HH:mm”“保存失败”。
  • 内容变化包括：模板名/分类/描述/标签、对象增删改、人物字段、路线/文字、图层显隐。
  • 缩放、平移、局部部署视图、当前选中的对象、右侧页签属于会话状态，不写入模板，不跨刷新保留。
  • 保存成功后更新模板的“更新时间”；模板库按该时间排序。

首次使用与数据说明

  • 首次进入编辑器时显示一次可关闭的提示：“模板保存在当前浏览器，不会上传；清除浏览器数据会丢失，建议定期导出备份。”
  • 帮助抽屉内常驻“数据存储说明”，并解释无痕模式/换浏览器/清缓存的影响。

刷新与恢复

  • 刷新页面后，加载最近一次成功保存的模板；若上次保存失败，加载更早的成功版本，并提示“有未保存的更改已丢失”。
  • 撤销/重做仅在当前编辑会话内有效，最多 30 步；刷新后清空，不写入本地存储。
  • P0 不提供自动版本历史；用户需要保留旧版时使用“复制”或“导出”。

保存失败

原则：不得把失败显示成成功。本地存储不可用、配额不足或写入异常时，顶部出现常驻横幅：“保存失败，当前修改仅在本页内存中”，并提供“重试保存”“导出备份”两个动作。用户可以继续编辑，但刷新/关闭页面会丢失未保存内容。

多标签页与版本

  • P0 不保证多标签页并发编辑：同一模板在两个标签页打开时，后保存者覆盖先保存者。帮助中明确“建议只在一个标签页编辑同一模板”。
  • 导出文件带 schemaVersion；应用读取到更高版本时，提示“文件由更新版本创建，可能无法完整显示”，并允许只读导入或取消。
  • 应用升级后读取旧版本数据时，应在本地完成兼容迁移；迁移失败不得删除原数据，提供导出失败数据的入口。

FR-09 导入与导出 P0

目的：用文件完成跨设备、跨人的传播；导入必须“先预览、再确认”，不能把坏文件直接塞进模板库。

导出

  • 编辑器顶部“导出”打开弹窗：显示模板名、分类、人物数、标点数、路线数，输入/确认文件名，点击“下载 JSON”。
  • P0 只导出当前模板；不包含图片、缩略图或浏览器本地设置。文件为 UTF-8 JSON。
  • 默认文件名：百业战战术_{模板名}_{YYYYMMDD}.json；清除文件名中的 \ / : * ? " < > | 等非法字符，长度上限 80 字。
  • 导出成功后 Toast“已导出”，并提示“可通过群聊发送该文件”。

导入入口与预览

  • 模板库顶部“导入”打开导入弹窗；支持拖拽文件到弹窗或点击选择。
  • 选择文件后先解析并显示：文件名、模板名、人物数、标点数、路线数、更新时间、schemaVersion、校验结果。
  • 导入方式默认“作为新模板导入”；也可选择“覆盖现有模板”并指定目标模板。
  • 点击“确认导入”后才写入本地；成功后 Toast“已导入”，并打开新模板或留在模板库（由用户在弹窗中选择，默认打开）。

校验规则

检查项不通过时的处理
文件类型与大小仅接受 .json；超过 5 MB 拒绝，提示“文件过大”。
JSON 可解析解析失败提示“文件不是有效的 JSON”，不写入任何数据。
格式标识必须为 yysls-baizhan-tactic；否则提示“不是本工具的模板文件”。
schemaVersion高于当前支持版本时提示可能不兼容，允许取消或只读导入；低于当前版本时尝试迁移。

对象合法性对象类型必须是已知类型；坐标必须在 0–1；人物名称 1–12 字；超限对象拒绝整份文件。
数量上限对象总数 ≤200，人物 ≤60；超出时拒绝并提示“请拆分模板”。

冲突与覆盖

  • 同一模板 ID 已存在：默认仍作为新模板导入（生成新 ID），不自动覆盖。
  • 同名模板已存在：显示非阻塞提示“已有同名模板”，允许导入；列表通过更新时间区分。
  • 覆盖导入：必须选择目标模板并二次确认；确认框显示“将用文件内容替换【目标模板名】，目标原有内容不可恢复”。
  • 覆盖后：目标模板的 ID 与创建时间保留；名称、分类、地图、描述、标签、图层、对象全部以导入文件为准；更新时间取当前时间。

安全与异常

  • 导入文本一律按纯文本渲染；禁止把文件内容作为 HTML/脚本执行，防止 XSS。
  • 不加载导入文件中的外部 URL、图片或字体；P0 文件不包含二进制资源。
  • 导入过程中不修改现有模板，直到校验通过并确认；失败时保留原模板库不变。
  • P1 增加：导出 PNG、导出全部模板备份、只读分享链接。

9.4 坐标、ID 与版本

  • 坐标 x/y 使用地图宽高的归一化比例（0–1，保留 4 位小数），原点为地图左上角；地图缩放/窗口变化不改变坐标。

10.3 可用性与离线

  • 产品为纯前端页面，打开后不依赖服务端接口；页面已经加载的情况下，断网仍可继续编辑与导出。
  • P0 不提供 PWA 安装、后台同步或离线包；刷新或重新打开页面仍需能正常加载页面资源。
  • 本地存储不可用（无痕模式限制、配额不足、浏览器策略）时，允许继续在内存中编辑，但必须常驻“保存失败”提示，并提供“重试保存”和“导出备份”。
  • 不把“关闭页面后恢复”作为保存失败时的兜底承诺；未保存内容在刷新或关闭后丢失，文案必须提前说明。

10.4 数据、隐私与留存

  • 不要求登录，不建立账号体系；模板内容不上传服务器，也不做跨设备自动同步。
  • P0 不接入第三方统计、广告或用户行为埋点；若后续引入，需在帮助中明确说明并在导入/导出相关页面提示。
  • 数据只存在当前浏览器与当前设备；清除浏览器数据、更换浏览器、使用无痕模式都可能导致模板不可见。
  • 产品不提供自动云备份；“导出 JSON”是用户自行备份与迁移的唯一 P0 手段。
  • 导出文件包含模板名、分类、备注、人物花名与标点信息；分享前由用户自行确认是否包含内部信息。
  • 删除模板、分类按 08.2 的确认矩阵执行；删除后的数据不进入回收站，用户需依赖导出备份恢复。

10.5 安全

  • 导入文件一律视为不可信输入：先校验格式、字段、坐标、数量与长度，校验不通过不写入任何数据。
  • 模板名、人物名、备注、文字标注等全部按纯文本渲染；不把文件内容当作 HTML、样式或脚本执行。
  • 不加载导入文件中的外部图片、字体、链接或远程资源；P0 文件不包含二进制资源。
  • 导出文件名按 FR-09 清洗非法字符并限制长度，避免路径穿越或异常文件名。
  • 产品不收集凭证、不接入支付、不执行任何服务端指令；安全边界以浏览器同源策略与本地文件解析为限。

11核心流程

流程只描述用户可见的步骤、分支与结束条件。每一步对应第 07 节的功能编号，不重复字段与校验细节。

11.1 首次新建并导出一份战术

触发：用户第一次打开产品，模板库为空。完成条件：模板出现在模板库，且用户成功下载一份 JSON。

打开模板库→ 新建模板→ 填写名称/分类→ 进入编辑器→ 添加人物→ 放置标点/路线→ 自动保存→ 导出 JSON
  1. 空状态显示“还没有战术模板”，提供“新建空白模板”和“导入模板文件”两个入口。
  2. 新建弹窗只要求模板名；分类默认“未分类”，地图固定为百业战示意底图。名称为空时“创建”不可用。
  3. 创建成功后直接进入编辑器；此时即使未做任何编辑，模板也已写入本地，返回模板库可以看到。
  4. 用户按 C 打开“添加流派人物”，选择流派预设与数量，系统生成“翊1号”“翊2号”这类可改名称的人物并落在地图中心附近。
  5. 用户用 M 放置人墙、大鹅、发财树、野区首领、集合点等标点；用 R 画路线；用 T 写文字。所有操作立即在地图上生效。
  6. 停止编辑后自动保存，顶部显示“已保存 HH:mm”。
  7. 点击“导出”，确认文件名后下载；导出成功后提示“已导出，可通过群聊发送该文件”。

分支：名称为空、超过 40 字或只含空白时阻止创建；分类不存在时先创建分类或落入“未分类”；对象达到 200 个时阻止继续新增并提示拆分模板。

11.2 打开既有模板继续编辑

触发：用户需要查看或修改上一场的战术。完成条件：修改已保存，返回模板库后卡片信息与更新时间正确。

模板库→ 搜索/选分类→ 打开模板→ 编辑→ 自动保存→ 返回模板库
  • 模板库按更新时间倒序展示；搜索匹配模板名、分类、标签与人物名。
  • 打开模板时恢复上次保存的对象、图层显隐与模板信息；缩放、平移与选中状态不恢复。
  • 返回模板库不打断保存；若仍有“保存中”，卡片先显示旧更新时间，保存成功后刷新。

11.3 导入模板文件

触发：用户从队友或旧设备拿到一份 JSON。完成条件：模板出现在模板库并可正常打开；任何失败都不改变现有模板库。

导入入口→ 选择/拖拽文件→ 解析与校验→ 预览摘要→ 选择导入方式→ 确认导入→ 打开或留在模板库
分支用户看到什么系统行为
文件不是 .json 或超过 5 MB“仅支持本工具导出的 JSON，且不超过 5 MB”不解析，不写入
JSON 无法解析“文件不是有效的 JSON”不写入，保留弹窗供重新选择
格式标识不符“不是本工具的模板文件”不写入，不提供强制导入
schemaVersion 高于当前支持“文件由更新版本创建，可能无法完整显示”允许取消或只读导入；只读导入不覆盖现有模板
必填字段缺失或对象非法列出前三条具体问题整份拒绝，不部分导入

11.4 保存失败与恢复

触发：本地存储不可用、配额不足或写入异常。完成条件：用户明确知道“未保存”，并能重试或导出备份。

  1. 顶部出现常驻横幅：“保存失败，当前修改仅在本页内存中”，附“重试保存”“导出备份”。
  2. 用户可继续编辑；保存状态保持“保存失败”，不得短暂显示“已保存”。
  3. 点击“重试保存”：成功后横幅消失，状态变为“已保存 HH:mm”；失败则更新原因摘要与时间。
  4. 点击“导出备份”：按当前内存内容导出 JSON，即使模板尚未成功写入本地也可导出。
  5. 用户刷新或关闭页面：加载更早一次成功保存的版本，并提示“有未保存的更改已丢失”。

11.5 误删与撤销

触发：用户删除人物、标点、路线或文字。完成条件：对象恢复或用户确认放弃。

选中对象→ Delete→ 对象消失 + Toast→ Ctrl/Cmd + Z→ 对象恢复
  • 删除对象不弹确认；Toast 显示“已删除 · 撤销”，点击“撤销”等价于一次撤销操作。
  • 撤销栈最多 30 步，仅当前编辑会话有效；刷新后清空。
  • 删除模板或分类仍需二次确认，且不在撤销栈内；确认后不可恢复。
  • 撤销后若对象原本处于选中状态，恢复时重新选中；属性面板同步刷新。

11.6 备份、迁移与换设备

触发：用户更换浏览器、清理缓存或要把战术发给队友。完成条件：接收方成功导入并能打开同一张图。

  1. 发送方在编辑器导出当前模板 JSON，文件名包含模板名与日期。
  2. 接收方在模板库点击“导入”，选择文件，确认预览中的模板名、人物数与标点数。
  3. 接收方选择“作为新模板导入”，确认后自动打开；分类不存在时创建或落入“未分类”。
  4. 双方各自在本地继续编辑，互不自动同步；后续变更需再次导出/导入。

P0 不支持整个模板库一键备份、只读分享链接或云端迁移：全量备份与只读分享链接列入 P1，云端迁移属于 P2 的账号与云同步范围。
